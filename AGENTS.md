# AGENTS.md

Working notes for AI agents and contributors. Keep changes consistent with the
existing code; read nearby files before inventing new patterns.

## What this project is

DataSnapper is a self-hosted, single-user web portal for a GDPR privacy-rights
case file. Everything stays local: SQLite under `DATA_DIR`, media on disk, no
telemetry. The only outbound calls are optional LLM requests when the user
explicitly enables them.

Hard constraints:

- No analytics or telemetry.
- No SMTP/IMAP; letters are exported and marked sent manually.
- No Node/asset build step. CSS and JS are hand-written; HTMX is vendored.
- Letter templates are practical starting points, not legal advice.
- AI is opt-in and must never send data before the user enables it.

## Stack

Django 5.2, Python 3.12, SQLite (WAL), HTMX, hand-written CSS, WeasyPrint,
Gunicorn and WhiteNoise. Configuration is environment-driven; see `README.md`
and `.env.example`.

## Commands

```bash
make install          # venv + dev dependencies
make migrate          # migrate + seed templates
make run              # local dev server on :8000
make test             # pytest
make lint             # ruff check + format --check
```

Raw equivalents:

```bash
.venv/bin/pytest
.venv/bin/ruff check .
.venv/bin/ruff format --check .
```

Always run tests and ruff before finishing a change. pytest uses
`config.settings_test`; its fixtures isolate data, media, backups and the
Fernet key per test.

## Layout

```
config/          settings, URLs, WSGI/ASGI
core/            dashboard, settings, search, calendar, backups, shared models
core/llm/        provider adapters and config for optional AI assistance
companies/       organisations, contacts, data inventory
cases/           cases, rights/checklists, deadlines, transitions, tasks
correspondence/  letter templates, messages, attachments, PDF/EML export, evidence;
                 AI prompt building in assist.py
audit/           hash-chained append-only audit log
templates/       global HTML templates and the PDF letter layout
static/          hand-written CSS/JS and vendored htmx.min.js
tests/           pytest suite
docker/          Dockerfile, entrypoint, Caddy example
```

Business logic belongs in the app's `services.py`. Views stay thin. Dependency
direction is `core` ← `companies` ← `cases` ← `correspondence`; `audit` is
cross-cutting. `staticfiles/` is generated by `collectstatic` — never edit it.

## Domain rules

- Case references look like `DSAR-2026-0001`; the prefix comes from
  `AppSettings` and references are generated in `cases/services.py`.
- Change case status only through `TRANSITIONS` and `transition_case()`.
- Deadlines: one calendar month after `sent_at`, clamped to month end
  (`core.utils.add_months`). An extension is three months from send.
- A case's checklist is per-right JSON from `cases/rights.py`; changing the
  right resets it.
- Editing a template creates a new version and deactivates older ones.
  `Message.template_version` freezes the text of sent letters.
- Only draft messages may be deleted; sent messages stay in the file.
- Use `timezone.localdate()` / aware datetimes, never naive datetimes.

## Privacy and security invariants

- Log meaningful user actions with `audit.services.log()`. The audit log is
  append-only and hash-chained; admin add/change/delete are disabled.
- Identity documents use Fernet via `encrypted_file`; never expose decrypted
  content in logs. Downloads of identity documents are audited.
- Attachments record SHA-256, size and MIME; uploads are capped at 25 MB.
- `LoginRequiredMiddleware` protects everything except login and `/healthz`.
- `secret.key` and `field.key` live in `DATA_DIR` and must never be committed.
- Do not put secrets in the repo; `.env` is intentionally ignored.

## AI assistance invariants

- AI is off by default. Never send anything to a provider unless
  `llm_enabled` (or `LLM_ENABLED=1`) is set.
- API keys are environment-only (`DEEPSEEK_API_KEY`, `OPENAI_API_KEY`,
  `LLM_API_KEY`). Never store them in the database, forms, templates or logs.
- `core/llm/` contains the provider adapters; `correspondence/assist.py` builds
  prompts, validates output and owns AI services. Views stay thin.
- Default placeholder mode: do not include profile/company details in prompts
  unless `llm_share_personal_data` is on. Never send attachments, identity
  documents, audit rows or other cases.
- Audit `llm.generate` with provider, model, mode, token counts and a prompt
  hash. Never store prompt or response bodies in the audit log.
- Treat model output as untrusted text: validate placeholders with
  `missing_variables`, cap lengths, and save through `create_ai_draft()` or
  `apply_ai_scope()` so the timeline and audit stay consistent.
- DeepSeek: send `thinking` explicitly. Disable it by default; when reasoning
  is on, omit `temperature` and never read `reasoning_content`.
- Tests must not hit the network. Monkeypatch `core.llm.generate` or the
  adapter's `request_json` seam.

## Conventions

- Ruff: double quotes, line length 100, `from __future__ import annotations`.
- Use `TextChoices` for enums and function-based views with `@login_required`
  / `@require_POST`.
- For HTMX toggles, return the relevant partial when `HX-Request` is set.
- Forms use `StyledFormMixin`; render fields with
  `templates/partials/form_fields.html`.
- For meaningful state changes, add a `CaseEvent` to the timeline **and** an
  audit entry.
- Commit migrations. Seed data must be idempotent; built-in templates are
  keyed by `(slug, locale)` and need both EN and NL versions.

## Docker and CI

The Docker context is the repo root; the Dockerfile is `docker/Dockerfile`.
The entrypoint runs migrations, `ensure_admin`, `seed_templates`, then Gunicorn
as the `app` user. `/data` is the persistent volume; Compose maps
`8080:8000` and health-checks `/healthz`. `docker-compose.yml` supplies local
defaults via `${VAR:-default}`, so it runs without a `.env` file; a `.env` or
exported variables override those defaults.

Workflows:

- `.github/workflows/ci.yml` — ruff and pytest.
- `.github/workflows/docker-publish.yml` — builds on code-changing pushes and
  publishes `ghcr.io/grogier/datasnapper` with branch/tag/sha tags plus
  `latest` on the default branch.

## Recipes

- New GDPR right: add it to `cases/rights.py`, add EN/NL seed templates if
  needed, and test the checklist/transitions.
- New model field: model → migration → form/admin if relevant → template → test.
- New page: view → named URL → template extending `base.html` → nav entry →
  page test in `tests/test_views.py`.
- New management command: `*/management/commands/`; keep it idempotent and safe
  to run on startup.

## Gotchas

- `DATA_DIR` must be writable, including in tests.
- Production uses manifest static storage; tests use plain storage.
- Don't bypass `transition_case`, `send_message`, `store_attachment`,
  `create_ai_draft`, `apply_ai_scope` or `audit.services.log`.
- Don't enable AI by default or add a provider call outside `core/llm/`.
- Don't commit generated data, SQLite files, media, `.env` or `staticfiles/`.
